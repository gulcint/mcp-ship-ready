## Plan
**Stack kararı: TypeScript, Node native type-stripping (build adımı yok).**
Gerekçe: `node --experimental-strip-types` (Node >=22.6.0, kararlı) ile
`.ts` dosyaları doğrudan çalıştırılabiliyor; CLI arg parse (`node:util`
`parseArgs`) ve test runner (`node:test`) Node çekirdeğinde olduğu için
**çalışma zamanında sıfır bağımlılık** — kullanıcı plugin'i kurup
`npm install` çalıştırmadan `/mcp-ship-ready:scan` kullanabilir.
`typescript`/`eslint`/`typescript-eslint` yalnızca dev/CI'da gerekir.
Hedef taranan repo dili (TS/Python) ile plugin'in implementasyon dili
bağımsız (ticket'ta izin verilen teknik karar).

Not: `typescript-eslint@8.70.1` henüz TypeScript 7.x'i desteklemiyor
(peer dep `<6.1.0`), bu yüzden `typescript@^5.9.3` sabitlendi.

Dosya yapısı:
- `.claude-plugin/plugin.json` — plugin manifest (name/version/description/
  author/license).
- `commands/scan.md` — `/mcp-ship-ready:scan <repo-path>` slash komutu,
  `${CLAUDE_PLUGIN_ROOT}/src/cli.ts`'i Bash ile çalıştırır.
- `src/cli.ts` — CLI giriş noktası (`parseArgs`, exit code 0/2).
- `src/scanner/index.ts` — `scan()` iskeleti; gerçek kural motoru
  task-2026-09-25-0003'te eklenecek, şimdilik boş bulgu döner.
- `src/report/format.ts` — bulguları insan-okunur metne çevirir.
- `tests/**` — `node:test` ile CLI/scanner/report testleri (uçtan uca
  çalışan, atlanmamış).
- `package.json`, `tsconfig.json` (`allowImportingTsExtensions` gerekli —
  `.ts` uzantılı import + `noEmit`), `eslint.config.js` (flat config).
- `.github/workflows/ci.yml`'a izole `node` job'ı eklendi (`test-integrity`
  job'ına dokunulmadı): `npm ci` → typecheck → lint → test →
  `claude plugin validate .`.

`pyproject.toml` bu ticket'ta oluşturulmadı — Python, plugin'in kendi
implementasyon dili olarak seçilmedi (TS tercih edildi, gerekçe yukarıda).

## Riskler / Güvenlik Notları
- Sıfırdan kurulan bir CI job'ı yanlışlıkla mevcut `test-integrity`
  job'ını bozabilir — CI değişikliği izole bir job olarak eklendi
  (`node`), mevcut job'a dokunulmadı.
- Lisans seçimi: MIT — geri dönüşü nispeten kolay, insan onayı
  gerektirmez; Geçmiş'e not düşüldü.
- `claude plugin validate .` bir uyarı veriyor: "CLAUDE.md at the plugin
  root is not loaded as project context". Bu, repo kökündeki CLAUDE.md
  dosyasının şirketin governance dosyası olması (plugin skill context'i
  değil) nedeniyle beklenen bir durum — `skills/<name>/SKILL.md`'ye
  taşınması bu dosyanın amacını (proje kuralları) bozar. Bu yüzden CI'da
  `--strict` KULLANILMADI (`claude plugin validate .`, `--strict` değil);
  `--strict` kullanılsaydı bu uyarı CI'ı kırmızıya çevirirdi. Kabul
  kriteri "hatasız geçer" diyor, "uyarısız" demiyor — plain validate exit
  code 0 döndürüyor.
- CI job'ı Node 22 kullanıyor (`actions/setup-node@v4`,
  `node-version: "22"`); yerelde yalnızca Node 26 mevcut olduğu için
  `--experimental-strip-types` Node 22'de bu makinede doğrulanamadı — flag
  Node 22.6.0'da eklendi ve resmi Node değişiklik günlüğüne göre 22.x boyunca
  kararlı; CI'da ilk çalıştırmada doğrulanmalı, sorun çıkarsa
  `node-version`'ı 24'e çekmek düşük riskli bir düzeltme.
- Gerçek müşteri verisi risk taşımaz (BRIEF "Veri" bölümü) — bu ticket
  sadece iskelet kodu içerir.
